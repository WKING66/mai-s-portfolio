# 博客 Markdown 编辑

博客新建与编辑共用沉浸画布。编辑期间仅维护同一份 ProseMirror 文档，Markdown 只在加载、保存和导出边界转换；没有整篇源码双栏或每次按键全文同步。

## 写作与导航

- 点击正文编辑；选中文字显示格式工具栏，空段落输入 `/` 插入内容块。查询超过 6 个字符或按右方向键后关闭菜单；光标重新经过已有 `/` 不重复打开。
- 列表项中 Shift+Enter 换行后，`/` 和加号作用于当前行；插入另一种列表时创建当前项内的子列表，保留外层编号或项目符号及其他列表项，可一次撤销。
- 普通粘贴 Markdown 使用与文件导入相同的完整解析，标题、表格、公式和代码按内容块呈现；Ctrl+Shift+V 保留字面文字。编辑器内部块复制、代码块与表格内粘贴继续使用原有处理。
- 保留跨段落与多块选择、复制、剪切、拖拽、撤销及重做。拖拽靠近画布上下边缘时画布连续滚动。
- 目录直接读取编辑文档的位置；点击目标展开必要祖先章节。正文折叠驱动目录状态，目录自身折叠不修改正文。
- 章节折叠由标题层级决定范围，只改变视图，不改写 Markdown 或撤销历史。代码块另有独立折叠。
- 标题、Slug、摘要、标签和下载开关在“文章设置”中单独保存。空标题、空地址可保存草稿，发布完整性由服务器校验；首次发布后地址锁定。网络资源权利确认属于正文资源准备，不随属性提交。
- 长文分批装载，同一文档加载完成前禁止编辑和保存；准备、读取、装载和排版共用一个骨架屏，进度数字紧随提示，直到正文完成绘制才撤下。

| 内容 | 编辑与保存边界 |
| --- | --- |
| 标题、段落、强调、删除线、引用、链接、列表 | 原位编辑，保存前校验完整语义往返 |
| GFM 表格、任务列表 | 单元格/行列操作、任务勾选；不提供 Markdown 无法表达的合并单元格 |
| 代码 | 原位修改代码、语言与文件名，独立主题、折叠和复制；语言可按名称/别名搜索，阅读与编辑共享 Shiki 完整语言目录，按需加载高亮 |
| Mermaid | 原位源码与图表，支持移动、缩放与全屏；无效输入保留上次有效预览 |
| 数学公式 | 行内及块公式原位输入，点击/方向键进入，失焦或 Esc 完成，上下键可退出块公式；无效公式保留源码 |
| 图片与附件 | 文件临时留在会话内，保存/导出时准备资源；正文保存稳定身份，不保存签名 URL |
| Alerts | 支持 NOTE、TIP、IMPORTANT、WARNING、CAUTION |
| 未支持语法及 HTML | 保留可见文字与语义边界，不执行作者 HTML；不提供脚注功能 |

## 代码块

代码超过 20 行时，编辑与阅读均默认显示部分预览；“展开全部代码 / 收起代码”文字按钮统一放在顶部工具栏，不随展开后的源码移到底部。短代码完整显示。折叠仅改变视图，完整源码、复制与撤销历史保持不变。拖选预览或编辑光标进入代码时展开，编辑文字选区覆盖代码时收起操作会保留选区并提示。

正文先显示完整纯文本代码，再由共享 Worker 按需加载语言语法、后台分词，逐块分批补充五套主题的颜色。编辑画布完整装载后才开始补色，收起代码的隐藏尾部在展开或光标进入后附加颜色装饰。长代码和长行不因全文/节点预算永久失去高亮，后台分词仍使用 Shiki 自身的超时保护。补色不修改代码、折叠状态或编辑历史，阅读者正在拖选代码时延后更新文本 DOM；旧版本或已卸载节点的后台结果直接丢弃。

代码格式化统一使用 dprint 框架，在后台线程按需加载语言插件；代码不上传第三方，不在首屏初始化格式化引擎。已覆盖 C/C++、Java、C#、Objective-C/C++、Protobuf、Python、Go、Shell、SQL/PLSQL，以及 JS/TS/JSX/TSX、JSON/JSONC/JSON5、HTML/Vue/Svelte/Astro/Angular、CSS/SCSS/Less、Markdown、YAML、TOML、GraphQL。

格式化只修改目标代码块，可一次撤销；语法错误、插件加载失败、代码在处理期间被修改/删除时，原内容与后来输入均保留。超过 200,000 字符的代码需拆分后格式化。高亮目录与格式化插件覆盖范围分别显示；未安装浏览器格式化插件的语言仍可正常阅读和编辑。插件首次使用需要下载（当前 Python 插件原始文件约 12 MB），不会阻塞正文输入和滚动。

代码输入使用块内独立编辑视图，修改仍进入同一篇文章的撤销历史；跨代码与正文的选择、复制、剪切和拖拽保持连续。主题菜单只改变当前代码块的展示，不修改正文。

公式保留完整渲染和 MathML；屏外公式按真实尺寸占位，进入视口或编辑时正常更新。实时预览改变公式大小时，输入浮层保持打开时的位置，滚动与窗口变化仍按正文位置调整。

工具栏附件按钮左侧的“编辑性能采集”图标可手动开始采样，最多持续 60 秒；停止后可复制诊断。采样仅在本机运行，不记录正文、输入字符或网络数据，不额外保存文章；自动停止不会打断输入焦点。

图标使用现有组件的 SVG 模式；首次打开菜单不再注入全局图标样式，避免长正文被整篇重新计算样式。
## 草稿、资源和发布

正式页面使用现有 Blog/Asset API，与开发环境 Showcase 的内存模拟保存分开：

1. 工具栏“保存正文”、正文中的 Ctrl+S 和正文最后一次修改后空闲 60 秒只保存正文，不校验或提交 Slug 等文章属性。正文未修改时不发送请求、不显示保存成功提示；编辑后撤销至原文也不重复上传。
2. 先准备当前正文实际引用的本地文件，再在 Worker 内执行完整 Markdown 校验，通过后提交草稿。上传失败保留文件与输入；已成功上传的文件在正文保存重试时复用。
3. “文章设置”中的“保存属性”和 Ctrl+S 只提交标题、Slug、摘要、标签与下载开关，不导出正文、不准备文件。未提交属性保持独立的未保存提示和错误信息，关闭设置再打开仍保留；“取消”明确放弃属性修改。未变化的既有 Slug 不重复校验格式，属性校验失败不阻止保存正文。
4. 创建使用 `requestId`；正文通过现有 `PATCH /api/v1/blogs/{id}` 更新，属性通过 `PATCH /api/v1/blogs/{id}/properties` 更新，两者共用服务器 `revision`，按顺序提交。没有新增正文接口或保留混合更新分支；断线重试沿用原身份和输入，确认结果后才提交后续编辑。
5. 保存响应只更新对应范围的服务器修订、资源引用与展示投影，不重建画布、不覆盖保存期间的新输入或另一范围未提交的属性。签名地址续期也不覆盖正文。
6. 修订冲突保留本地输入，读取最新管理状态并阻止盲目覆盖；可先导出当前 Markdown，再明确处理本地修改并重新读取。Slug 重复只在属性设置中提示。
7. 正文保存成功与资源就绪分别提示。资源未就绪时可通过“重试资源处理”明确提交同一正文重试资源准备。发布只提升已保存草稿；恢复最近正式正文不发布工作草稿；下架仅关闭公开入口。
8. 工具栏 Markdown 导出读取当前画布；文章操作中的服务器正文导出读取已保存内容，两者明确区分。
9. 站内离开同时检查正文和属性，使用保存/放弃/取消弹窗；浏览器刷新和关闭保留原生未保存保护。

正文与属性拆分需要前后端同步部署，不适用于仍接受混合更新请求的旧后端。接口及内容槽位语义见 [博客与 Document API](api/blog-document.md)。正式代码不再保留 Showcase 或 Milkdown POC 路由；模拟保存和上传仅存在于测试夹具中。

## 正文查找与替换

阅读页和编辑页的放大镜按钮打开正文查找。快捷键为 Ctrl/⌘ + F；编辑时 Ctrl/⌘ + Shift + F 直接打开替换。交互参考 [飞书文档查找与替换](https://www.feishu.cn/hc/zh-CN/articles/191994006277)。

- 按大小写精确匹配单行字面文本，结果显示命中计数；Enter/Shift + Enter 或上下按钮循环定位，Esc 关闭。普通命中黄色高亮，当前命中红色高亮。
- 范围仅限正文：包含正文中的章节标题、段落、列表、表格、代码与链接文字。文章属性标题、摘要、公式 LaTeX、Mermaid 源码、图片、代码文件名和链接地址不参与。定位时展开必要的折叠章节或长代码。
- 只有编辑状态提供替换；阅读页及完成编辑后的查看状态仅提供查找。跨样式匹配的替换文字继承首字符样式，匹配范围外的内容和格式保留。
- 替换为空表示删除文字，支持空格，不支持换行；内容相同或没有命中时不制造保存变化。
- 一次“全部替换”是独立的撤销步骤。面板提供撤销/重做替换入口，也可在正文使用正常撤销/重做；替换前后的输入分别保留各自的历史分组。替换仍进入当前未保存正文，按既有正文保存流程提交。
- 全部替换及其撤销/重做保留当前视口；单处替换后优先定位下一处，已到末尾则选择上一处，需要移动时平滑过渡（遵循系统减少动态效果设置）。关闭查找会清空查找词、替换词及状态，不保留旧定位；关闭后光标回到画布，重新打开不自动跳转。
- 替换后可直接在面板使用 Ctrl/⌘ + Z 撤销正文替换、Ctrl/⌘ + Shift + Z 或 Ctrl + Y 重做。若随后修改了查找或替换输入框，快捷撤销先交给输入框自身；面板的撤销替换按钮始终明确操作正文。

查找面板关闭时不扫描正文；打开后的派生查找在短暂停顿后更新，输入直接进入当前文档。搜索高亮及定位本身不保存文章或改写 Markdown。
