# 锚点首次刷新跳顶修复与验收

## 范围与分支

- 功能分支：`feature/anchor-refresh-scroll`。
- 父分支：`feature/project-cards-upload-component`，基线 `651b50f`。本次不合并。
- 只修复首页锚点首次刷新跳顶及水合后的二次定位，不修改认证、接口、数据库或项目业务。
- 实测环境：默认前端 `http://127.0.0.1:3000` → 维护者 IDEA/dev 后端 `9333`；桌面 Chromium，视口约 1902 × 984。没有使用替代端口或验收账号/密钥。

## 原因与处理

事实：Nuxt 的首次客户端启动把恢复模式设为 `auto`，后续站内导航则切成 `manual`。Vue Router 也会配置手动恢复并保存历史位置。刷新沿用了当前历史条目的恢复模式；点击其他锚点再回来后，第一次刷新携带 `manual`，SSR 内容先在顶部，客户端启动后才定位。第二次刷新已经携带 `auto`，所以表现不同。相关本地源码为 Nuxt `dist/pages/runtime/plugins/router.js` 和 Vue Router `dist/vue-router.js`，依赖版本未修改。

历史条目保存滚动恢复模式，`auto`/`manual` 的行为与新条目的继承规则可参见 [HTML 标准：历史条目与滚动恢复](https://html.spec.whatwg.org/dev/nav-history-apis.html)。

另一项实测回归：仅提前启用原生恢复仍不够。技术栈下继续阅读到 `scrollY=556` 后刷新，浏览器先恢复到 556，旧初始化分支又按 `#stack` 定位至 396，覆盖了真实阅读位置。

处理判断：保留已有路由滚动机制，只在新文档 SSR head 内同步启用原生 `auto`；首次水合不再调用第二次定位。后续站内锚点、前进/后退及减少动效适配继续由原有路由处理。不新增坐标存储、全局持续监听、会话请求或第三方依赖。两项改动必须配套，不能单独将初始滚动返回值改为 `false`。

## 浏览器操作与结果

按 browser-act 技能采用真实浏览器导航、原生 `location.reload()`，并检查绘制过程，而非只检查最终位置。临时探针仅在本轮标签页显式启用，最终全部移除；它不是产品功能或持久化方案。

| 操作 | 参数 / 路径 | 实际结果 |
| --- | --- | --- |
| 基线复现：点“项目”，再点“技术栈”，刷新；再次刷新 | `/#stack`，初次 `manual`、第二次 `auto` | 初次先顶后回技术栈，第二次正常；与反馈一致 |
| 修复后点“项目”，再点“技术栈”，原生刷新 | `/#stack`，刷新前 `scrollY=396`、`manual` | 新文档 `auto`，回到 396；水合后不再调用二次 `scrollTo`；高亮“技术栈” |
| 点“博客”，再点“技术栈”，首次原生刷新 | `/#stack`，刷新前 396、`manual` | 恢复 396；绘制回调和水合后均在技术栈 |
| 在技术栈下继续阅读，再刷新 | 手动滚动至 556，保留 `#stack` | 首次采样、绘制回调及水合后都为 556，不再跳回锚点起点 396 |
| 点“项目”并原生刷新 | `/#projects` | 刷新前后均为 1353；没有初始化二次定位 |
| 点“联系”并原生刷新 | `/#contact` | 刷新前后均为 2431（受文档底部上限限制） |
| 联系 → 技术栈 → 后退 → 前进 | 浏览器 `history.back()` / `forward()` | 后退到联系 2431；前进到技术栈 396，“技术栈”高亮 |
| 新文档直接访问带锚点 URL | `http://127.0.0.1:3000/?anchor-check=1#projects` | 原生片段定位至项目 1353，水合后不再覆盖 |
| 移除所有探针后重新加载 | `http://127.0.0.1:3000/#stack` | `scrollY=396`，高亮“技术栈”，客户端已水合，DOM 和全局均无探针 |

首次探针的相对脚本时间仅用于诊断，不能与以导航开始为基准的 paint 时间混算。最后使用无外部请求、无行为拦截的 inline 探针，统一记录 `performance.now()` 与 paint 条目；核心记录如下（毫秒，基准均为 navigation time origin）：

- 项目 → 技术栈 → 首次刷新：317.3ms 采样仍为 0，374.1ms 已为 396，首次绘制/FCP 456ms，绘制观察回调所见为 396。此序列恢复发生在首次绘制之前，非最终状态兜底。
- 阅读偏移刷新：182.8ms 第一次采样已为 556；FCP 316ms，绘制回调为 556；后续采样没有位置变化。
- 博客 → 技术栈 → 首次刷新：首个恢复采样约 359.6ms，FCP 条目为 356ms，绘制回调为 396。浏览器 paint 时间有粒度差异，该次记录不据此声称精确到毫秒的先后；它确认绘制回调与水合后的位置，前一序列提供明确的首绘前恢复证据。

会话资源计数在联系刷新后的该文档内为 0，随后的技术栈、后退、前进仍为 0；未因滚动新增请求。资源计数不等于完整代理审计，也不代表本轮验证了所有认证行为。
