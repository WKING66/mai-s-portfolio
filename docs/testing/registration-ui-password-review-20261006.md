# 登录注册页面与密码规则审核修正

日期：2026-10-06。本次为注册模块的审核修正，在 `feature/visitor-registration` 继续操作；父分支仍为 `feature/portfolio-seo`。修正起点 `7ddffd4`，不合并父分支。

## 最终需求与实现

- 登录、注册页采用共同的紧凑样式：缩小卡片、标题、输入框和间距；窄屏收起装饰介绍，短视口收起徽标/欢迎语，小屏为校验提示预留空间。
- 不通过 `overflow:hidden`、固定裁切高度或缩放整页掩盖内容。正常尺寸自然占一个视口；极小视口、浏览器放大或软键盘压缩时仍允许自然滚动，不截断操作入口。
- 去掉表单中的传输技术介绍、权限长说明和“保留空格/190 字节”提示。注册密码字段仅显示必要的字符规则。
- 注册密码先 trim 首尾空白，随后只接受可见 ASCII `!`–`~`：英文字母、数字、下划线与英文标点；至少 12 位。内部空格、制表符、换行、控制字符、中文、emoji、全角标点均拒绝，不静默删除内部字符。没有新增强制字符组合要求。
- 前端规范化后校验/加密，服务端解密后执行相同规范化和校验；不能绕过前端获得不同结果。服务端去首尾空白的范围与 JavaScript String.trim 一致，包括 Unicode 分隔符和 BOM。
- RSA 单条明文上限仍为 190 字节，属于底层安全校验，不再作为常驻页面说明。超长错误采用简短提示。
- 登录行为、Cookie/RSA/CSRF、账号角色、普通用户权限和独立 Redis 限流保持不变；不自动修改或迁移已有账号的密码。
