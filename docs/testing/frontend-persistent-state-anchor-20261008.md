# 首页刷新定位与账号快照持久化

日期：2026-10-08。

功能分支：`feature/frontend-persistent-state-anchor`。父分支：`feature/api-feedback-alerts`，起点 `9d2cb32`。本轮不合并 main、不推送。

## 业务规则与变更边界

1. 用户明确指出重复读取的是 `/account/profile`（昵称、头像），与 `/profile`（网站公开资料）不是同一业务事实。公开首页继续 SSR 读取 `/profile` 和公开项目，不在浏览器持久化 SSR 管理内容。
2. 当前账号的 session 展示信息与个人资料读多写少。首次没有有效快照时获取；同浏览器刷新和切页复用；成功登录、注销、修改昵称、绑定头像或修改密码沿用现有状态更新入口。
3. 服务端 Cookie、账号状态和角色授权仍是认证事实来源。浏览器快照只决定展示和请求前检查。受保护请求仍由后端最终校验。
4. 私有 OSS 签名头像地址会到期，账号资料不能永久视为有效；复用已有签名地址过期判断和刷新组件，只补取个人资料，不连带刷新 session。
5. 401 使旧快照失效并读取一次真实 session；鉴权/CSRF 403 通过已有统一拦截器更新 session。取消 OWNER 只撤销管理能力；正常登录账号保留。一般业务 403 不错误注销。失败写请求不自动重放。
6. 新锚点尚没有浏览器滚动历史时，刷新需要在 SSR 文档首帧恢复。保存实际阅读偏移，不能水合时再次滚到锚点覆盖阅读位置。用户开始交互后停止待完成的定位。

稳定核心是账号身份隔离、后端授权、写入后的共享状态更新、SSR 请求隔离和站内滚动规则。当前明确的变化点是浏览器快照失效、签名 URL 到期、跨标签页账号变化和初始 DOM 分段到达。

## 功能正确性

- Pinia `account` 为账号展示状态的唯一运行时数据源。client 插件保存经过投影的 localStorage 快照，启动时 `ensureSession` 优先恢复。
- 不保存密码、HttpOnly Cookie、管理实体、pending 或 error。版本不匹配、JSON 损坏、身份不匹配的资料和过期头像不能直接恢复为有效资料。
- 成功写入直接接受后端返回的最新个人资料，菜单和个人中心同步使用，避免随后再发冗余 GET。退出/密码修改/身份切换清理个人资料；跨标签页更新同样取消旧请求回填。
- 存储禁用/配额不足不阻断正常请求。会话查询出现网络/服务故障时保留“未知”状态，不把故障持久化为服务端确认匿名；后续初始化可重试。
- `pagehide` 保存当前完整相对 URL 与滚动坐标。同步 head 脚本在 SSR DOM 就绪时恢复；未有匹配记录时按实际锚点和 CSS 滚动边距定位。现有路由继续处理 SPA 平滑导航、历史返回与减少动效。
- AccountMenu 和 Auth 使用挂载前占位，避免浏览器恢复的私有状态与匿名 SSR 输出发生水合不匹配。

## 设计与职责边界

| 职责 | 唯一承载位置 | 复用关系 |
|---|---|---|
| 账号运行时状态与身份切换 | `stores/account.ts` | 菜单、个人中心、认证层共用 |
| 快照版本、字段投影与读取校验 | `utils/accountSnapshot.ts` | 不发请求、不决定服务端权限 |
| 存储订阅、跨标签页与卸载保存 | `plugins/account-snapshot.client.ts` | 仅浏览器应用生命周期 |
| 初始化、鉴权异常、CSRF、请求世代 | `useAuthState` / `authInterceptor` | 延续现有请求入口，没有第二套认证流程 |
| 个人资料读写状态与签名到期 | 现有 `useAccountProfile` / `useAssetUrlRefresh` | 延续现有 GET 去重和写响应接受 |
| 首文档定位、站内导航定位 | `utils/scrollPosition.ts` | 现有 Nuxt head 配置、router.options 共同使用 |

未新增持久化框架、Controller、后端缓存、登录 API 或特殊页面专用缓存。组件不直接读取 localStorage；快照不被当成授权凭证。

## 当前支持的扩展点

- 新增账号展示字段：调整既有 VO、Pinia 状态、快照字段投影及校验，不复制持久化插件或账号请求服务。
- 新增账号写操作：接受既有最新资料状态入口；身份失效使用统一认证入口。
- 新增需要签名过期刷新的账号资源：沿用签名到期判断和刷新组件。
- 新增首页锚点：使用实际元素 ID 与 CSS 滚动边距，定位脚本不列举项目、博客或联系等特殊分支。

## 主动没有提前设计的未来扩展

没有建设通用缓存 Registry、按页面的存储 Strategy、IndexedDB、跨设备推送、全站离线缓存或多版本迁移框架。当前快照版本变化直接按无缓存恢复；没有为已经删除的 API 增加适配或 fallback。

## Maintainability Review

- **新增同类能力修改位置**：新增锚点不修改恢复逻辑；新增账号展示字段需改变真实 VO 和一个快照投影/读取边界，调用组件沿用共享资料能力。
- **替换外部依赖**：改变存储方式集中于快照读写、client 插件及 store 的恢复/失效入口；账号表单、账号 API 和后端授权代码不受影响。
- **重复规则**：签名 URL 生命周期复用 `assetUrlsFresh`，角色判断复用权限函数，昵称/头像写入复用 `profile.accept`，鉴权错误没有散落到组件。
- **为测试而写的生产代码**：没有针对测试用户名、固定锚点位置或模拟接口写分支；生产逻辑不依赖测试后端。
- **Source of Truth**：服务端认证事实、Pinia 展示状态、localStorage 恢复副本三者职责明确；SSR 每个应用独立，未引入全局用户单例。
- **失败路径**：覆盖存储失败/损坏、资料过期、网络故障、401、鉴权/CSRF 403、账号切换中的旧响应、跨标签页更新、DOM 未完整到达和用户取消恢复。
- **配置、异常、日志**：复用既有 API 常量与 `ApiRequestError`。存储不可用仅降级缓存，无敏感日志。测试地址和浏览器路径只由测试环境提供。
- **后续复制风险**：没有第二套 profile/session 实现；新增普通账号操作不需要复制缓存或认证拦截器。未发现本轮明显结构性遗留。

## 技术债务与验证范围

- 浏览器缓存不会主动探测其他设备发生的账号变化；下一次受保护请求收到服务端拒绝后更新，这是本轮用户选择的失效模型。未建设实时推送或定时 session 轮询。
- 公开网站资料 `/profile` 仍在刷新时 SSR 读取；不在本轮账号快照范围内。
- 浏览器回归使用 Chromium 和隔离模拟后端；没有实际禁用真实账号、变更真实 OWNER 权限或写入真实数据库/OSS。本轮没有后端生产改动。
- 浏览器测试复用本地 Playwright 与浏览器可执行文件，不新增项目依赖；运行前需提供可用环境。Firefox/Safari 的真实首帧行为尚未实测。
