# Nuxt UI Toast 提示修正与验收

日期：2026-10-08。功能分支 `feature/nuxt-ui-toast-feedback`，父分支 `feature/api-feedback-alerts`，起点 `82f022c`。本轮提交后停止供审核，不合并、不推送；保留维护者已有改动。

## 业务规则与修正原因

操作反馈仅用于通知，不需要用户确认；通知在页面上方居中，显示和关闭不能改变页面布局，也不能阻止继续输入或重试。失败保留未保存输入，不自动重复写请求；SSR 读取失败在浏览器挂载后提示，过期账号响应不误报。

上一版把通知实现成 `UModal`，附带“知道了”按钮。已安装 Reka UI 的 `DialogOverlayImpl.vue` 会调用 `useBodyScrollLock(props.present)`；这种提示引入滚动锁与焦点管理，不符合当前通知需求。既有 UApp 已提供 Nuxt UI Toaster，无需另建弹窗组件或状态管理。

稳定核心是操作结果与业务失败语义；可预见变化是通知种类、统一外观与摆放位置。前者仍由调用方业务能力决定，后者分别由反馈常量、薄封装和 UApp 配置承载。

## 功能正确性

- UApp 使用 `toaster.position = 'top-center'`；通知固定在页面上方，不占业务内容位置。
- `useFeedback().success/info/error` 保持原函数调用方式。无确认 actions，提供组件库默认关闭按钮与自动消失行为；悬停、焦点暂停和队列由组件库管理。
- 通知不抢输入焦点，不挂载模态遮罩，不将页面设为 inert，也不进行 body 滚动锁。
- 操作成功后的路由跳转仍能看到结果；重复失败仍能提示，失败输入保留，只有明确重试才再次写入。
- 错误作为文本显示，不解析为 HTML。未知错误使用业务 fallback，公开读取错误不暴露原始请求地址；`AUTH_SESSION_CHANGED` 继续静默丢弃。
- 原账号快照、签名头像过期恢复、401/403 处理和锚点恢复链路未改变。

## 设计与职责边界

调用方负责业务动作与错误文案；`useFeedback` 只做消息映射和展示边界判断；Nuxt UI 负责通知状态、唯一标识、队列、Portal、动画、计时、关闭和无障碍行为。认证、缓存失效与 API 重试仍在原业务能力内。

删除 `FeedbackDialog.vue`、`FeedbackMessage`、旧模态颜色类、应用 WeakMap、消息数组与自建去重/开关逻辑。不保留新旧两套通知实现，不新增依赖、插件、通知 Pinia Store 或全局事件总线。

采用库自动生成的通知 ID，每次操作结果交给库处理；不按错误文案复用 ID，以免关闭动画期间的延迟删除影响随后同文案通知。

## 当前支持的扩展点

- 新页面直接调用现有三个函数，无需复制提示组件。
- 修改统一位置在 UApp 修改；修改种类标题、图标在 `FEEDBACK_KINDS` 修改。
- 若明确增加另一类通知，增加常量与相应函数即可，不新增 Controller、Service 或消息管理器。
- 更换展示库只涉及 UApp 与反馈封装；业务调用方不依赖 `useToast`。

## 主动未提前设计的未来扩展

不实现确认对话框、消息持久化、消息中心、自定义队列/去重/计时、可交互通知按钮或插件注册机制。这些并非本次需求，确认类业务应在真实需求到来时单独处理。

## Maintainability Review 与技术债务

| 检查项 | 结论 |
|---|---|
| 新增同类业务提示需要改多少位置 | 新业务调用方一处；不复制 UI 或消息管理 |
| 替换外部展示依赖需要改多少业务代码 | 业务调用方无需修改，适配集中在反馈封装与 UApp |
| 是否重复业务判断 | 本轮没有新增业务判断；过期账号响应过滤集中在反馈入口 |
| 是否存在为了当前测试通过的生产分支 | 无；测试按页面实际布局宽度计算中心，未修改库 CSS 迁就断言 |
| Source of Truth | 业务结果来自 API；通知状态由 Nuxt UI 管理；种类元数据来自反馈常量 |
| 失败路径 | 重复失败、未知错误、SSR 错误、旧账号响应、失败保留输入与显式重试均覆盖 |
| 配置、异常与日志 | 沿用现有 UApp、ApiRequestError 与认证错误常量；未增加日志或异常体系 |
| 下一次需求是否迫使复制粘贴 | 页面复用函数；不维护页面专属提示生命周期 |

本轮未发现需要保留的结构性通知债务。项目构建仍有现有依赖的 exports 弃用及构建耗时提示，本轮未为通知需求升级依赖。浏览器验收使用本机 Chrome，未声称已验证所有浏览器或移动设备。

## 测试与构建

- Node 24：Vitest 20 个文件、228 项通过；Nuxt typecheck 通过；生产 build 通过。
- 浏览器测试 8/8 通过，水合错误与未处理浏览器异常均为零。使用独立 Nuxt 构建、随机端口模拟 API、新 Chrome 上下文；不连接真实后端，不写真实数据库或 OSS。
