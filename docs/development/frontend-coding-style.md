# 前端编码规范

本文是 Nuxt 前端的代码分层与质量规范，由前端 Agent 维护。新增功能、修复、重构、依赖调整和测试修改前必须阅读，实现及提交前逐项自检。适用源码目录为 `mai-portfolio-frontend/`；Git、审批及 V0–V3 验证以 [Git 工作流](git-workflow.md) 为准，后端规则见 [后端编码规范](coding-style.md)。

## 先确定职责，再改代码

开始实现前，定位实际入口、状态持有者、共享规则、外部依赖和现有测试，再决定文件归属。每个新增文件须能用一句话说明职责及实际调用方；已有实现能承担时直接复用。目录划分服务于当前业务，不为单个小函数机械加层，也不为假设中的扩展创建空目录、通用框架或多套实现。

规则落实到本次受影响的代码；发现旧结构偏差时定向修正，不借修复全仓搬迁或重排。涉及重大架构、功能退化或接口语义变化时按共同工作流确认。

## 目录与职责

以下路径均相对于前端应用目录。当前具体文件入口见 [前端代码结构](../../resources/frontend-structure.md)，该说明不另立分层规则。

| 位置                                               | 负责                                         | 归属限制                                                                                                                |
| -------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `app/pages/`、`app/middleware/`                    | 路由参数、页面装配、访问入口与导航           | 页面把独立业务交互交给对应组件/会话；访问控制继续复用既有认证能力                                                       |
| `app/components/<业务>/`                           | 业务界面、节点视图、交互反馈及必要的业务装配 | 沿用 account、admin、auth、blog、editor、profile、project、site 等同级分类；不把解析器、请求协议和通用算法堆进组件      |
| `app/components/ui/`                               | 无业务归属的展示和交互原语                   | 通过 props/events 等明确接口工作，不持有博客会话、权限决策或业务请求                                                    |
| `app/composables/`                                 | Vue 响应式状态、生命周期、异步会话协调       | `useX` 用于真实的状态或生命周期复用；纯规则函数放所属 utils，不为改名包一层 composable                                  |
| `app/stores/`                                      | 确需跨页面共享的应用状态                     | 当前文章、编辑器实例、光标、选区、上传队列等会话状态留在对应会话；不得因多个子组件使用就升级为全局状态                  |
| `app/api/`                                         | 请求/响应类型、端点调用、传输及错误规范化    | 沿用既有认证/请求基础能力；不渲染 UI，不承载编辑文档、排版与解析规则；DTO 与已确认后端契约同名同义                      |
| `app/utils/<领域>/`                                | 领域规则、转换及明确的运行时适配             | 沿用 account、assets、blog、editor、markdown、project、site；DOM/ProseMirror 专用逻辑归 editor 对应职责，不伪装成纯函数 |
| `app/workers/`                                     | 后台任务的消息收发、调用和错误返回           | 规则实现复用所属 utils；页面与 Worker 不能各维护一份解析或序列化规则                                                    |
| `app/constants/`、`app/types/`                     | 真实共享常量、声明和环境类型                 | 专用类型、常量就近放在所属领域；只有确需跨领域共享或环境声明才放这里，不作为杂物目录                                    |
| `tests/unit/`、`tests/fixtures/`、`tests/support/` | 按领域组织的功能测试、固定输入、测试替身     | 测试与替身放在 app 外，保持类型检查；模拟保存、模拟上传和固定测试数据不得成为生产代码的默认实现                         |

Nuxt 配置、插件、静态资源和服务器路由按框架职责放置；配置入口不承载正文业务规则。文件新增到现有职责目录，组件根目录和 utils 根目录不重新积累散落的业务文件。存在独立业务时建立明确的同级分类，不创建 common、helpers、misc 等无法说明归属的收纳目录。

## 依赖方向与接口

- 页面/业务装配组件调用会话、API 和领域能力；展示组件接收必要数据并发出事件。会话协调状态与副作用，utils 实现所属规则与适配。底层规则、API、store、Worker 不反向导入页面或界面组件，不通过循环导入完成初始化。
- 跨领域确需复用时调用对方明确导出的接口；共享层不依赖某个页面的业务状态。不创建只转发一次调用的 service、factory、registry 或全量 barrel 来掩盖依赖关系。
- 跨文件类型由语义持有者定义。请求类型跟随 API 契约，编辑会话契约跟随 session；使用 `import type` 引用，不为了取类型而导入 Vue 组件或制造实现互相引用。不要为同一含义复制 DTO、常量、枚举和校验规则。
- 外部副作用通过明确接口进入会话，例如注入保存/上传入口；正式路径必须接入真实实现。缺少依赖时明确失败，不静默模拟成功。测试通过相同接口提供替身。
- 一个业务事实只维护一个规则来源。阅读页、编辑页、Worker 或导入流程需要相同语义时复用已有规则；差异以真实调用场景解释，放在对应适配处，不复制一条几乎相同的完整管线。

## 编辑器内部归属

`utils/markdown/` 管理阅读/编辑共享的解析、公式语法、代码语言和高亮等能力；`utils/blog/` 管理章节、资源和 slug 等博客规则。`utils/editor/` 内部沿用以下职责，不因新增节点类型再嵌套一套全功能编辑器：

- `markdown/`：画布导入、导出、序列化及完整语义校验。
- `session/`：初始化、保存接口与资源会话、节点位置索引、业务持久化适配。
- `interaction/`：选区、命令、拖拽、表格、剪贴板及章节交互。
- `code/`、`math/`：代码输入/格式化，以及公式预览调度/布局等专用能力。
- `diagnostics/`：明确开启的诊断采样；诊断不成为正常编辑的前置条件。

业务装配者连接文章 API、上传、正文保存和属性保存；画布组织者负责界面交互，文档会话维护编辑文档及异步任务。共享阅读组件可复用渲染能力，但只读 DOM 不能直接作为可编辑 DOM；不能为复用而破坏 ProseMirror 文档、事务或选区。

新增职责先查现有模块与调用点。拆分较大文件以可独立理解的状态、规则或副作用为单位，不按任意行数截取，也不只把长函数搬到另一个万能文件。

## 状态、数据与性能

- 同一编辑会话以当前 ProseMirror 文档为正文事实来源。Markdown/JSON 快照仅在导入、导出、保存等明确边界创建，不在每次输入时生成另一份全文状态用于比较或同步。
- 输入、删除和当前操作的视觉反馈优先完成。目录、块控制柄、统计、高亮和公式预览等派生任务按受影响范围、用户操作和空闲时机调度；合并过期任务，不把全树扫描、全文序列化、重复解析或同步强制布局塞进每次按键。防抖用于可延迟的派生工作，不用于拖延字符进入文档。
- 更新已有节点和位置映射，保持无关节点及其高成本实例稳定；不能因局部编辑重建整篇视图。Worker 复用同一规则处理必要后台任务，保存等待当前版本校验成功；失败不能静默回退成主线程全文运算或纯文本保存。
- 内容、文章属性和视图偏好分别维护状态。正文/属性分别判断未保存变化并按现有契约提交，无改动不请求保存；折叠、主题和目录操作不改写 Markdown 或制造正文 dirty。
- 异步响应携带必要的会话/版本判断，旧结果不覆盖新输入；失败保留可恢复的输入和具体原因，不冒充保存成功。资源稳定身份来自实际上传结果，临时引用在保存边界转换，显示 URL 的刷新不改写正文身份。
- 会话关闭时释放自己持有的 Worker、监听、观察器、定时器和临时预览 URL。共享资源由其实际持有者释放，子视图重挂载不能关闭仍被业务会话使用的资源。
- 节点内控件只接管自己的交互事件；保留普通文本选择、多块选区、拖拽、撤销/重做和中文输入。输入、滚动、目录跳转、折叠与公式/代码编辑的组合检查用于识别联动问题，不以单次按键耗时代表整体流畅度。

## 命名、可读性与工具

文件名表达业务或稳定职责，不使用轮次、日期、v2、final 等开发阶段名称区分生产实现。迁移优先替换原实现，调用切换后清理失效版本；需要兼容时说明实际调用方、语义差异和退出条件。

TypeScript 使用明确的输入输出与失败结果；外部不可信值先收窄再使用。不以 `any`、重复断言、关闭规则或吞异常掩盖契约问题。框架类型存在真实差异时，仅在最小适配处转换并说明依据。

排版遵循应用内 `.editorconfig`、`.prettierrc.json` 与 `eslint.config.mjs`；前端不继承后端 Java 的格式工具禁令。控制流程使用大括号并分行，多语句回调展开，不嵌套三元表达式。只格式化任务涉及的文件，不混入无关重排。注释说明业务原因、生命周期、失败结果或框架限制，不描述显而易见的语法。

## 迁移、清理与测试

1. 移动或合并文件前，检查实际调用方和现有替代能力。变更后搜索静态导入、动态导入、Nuxt 自动组件名/模板标签、Worker URL、CSS 选择器、测试夹具及文档引用；不能只修 TypeScript 直接 import。
2. 删除旧实现前确认生产入口已切换、没有活动调用方。历史测试先区分退役协议与仍有效的行为：删除前者，将后者迁到当前入口；保留失败路径、内容安全、多选、拖拽、公式、撤销和保存一致性的有效保障。不能仅因名称含 Showcase、时间久或测试失败就删整套用例。
3. 测试从真实接口验证用户可观察行为及必要失败路径，不为迁就测试保留死代码、测试开关或生产探针。不把测试替身结果称为真实浏览器/服务器验证；用户明确要求保留的诊断工具按正式功能维护。
4. 演示实现完成使命后从运行路径移除。临时脚本、录制、截图和性能报告留在 private，构建缓存与生成类型不当作源码提交；材料分类和清理按共同工作流执行。
5. 按风险选择关联检查，命令以应用 `package.json` 为准，包管理器使用 pnpm。类型检查应覆盖应用和独立测试目录。仅文档修改按 V0，不运行应用测试或构建；已通过且未受影响的检查不重复运行。

## 提交前必须核对

以下任一项不满足时，先修正本次改动；需要重大取舍时按共同工作流确认，不以“测试已过”跳过：

- 每个新增/移动文件的职责和实际调用方明确，放在正确目录；依赖方向无倒置、无循环。
- 同一规则与业务状态的持有者明确；没有第二套解析/校验、镜像类型、隐式全局状态或模拟成功路径。
- 文件移动的所有入口引用已核对，旧实现、无调用导出与无用测试已退出；有效旧断言已保留或迁移。
- 变更覆盖失败、版本过期、取消及释放路径；局部更新没有扩大为全文工作，没有退化选区、拖拽、输入或撤销。
- 验证范围与实际风险相称，结果及未验证部分如实说明；只暂存本任务文件，依赖/接口变化按共同规范交付。

当前 lint、类型检查和构建不能自动证明分层正确或没有交互退化，上述职责与依赖核对属于人工 Review 的完成条件。规范或结构发生已批准的变化时同步更新本文件与必要入口说明，不另建一份互相矛盾的规则。
