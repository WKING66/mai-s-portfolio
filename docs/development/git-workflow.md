# Git 协作与分级验证规范

任务驱动开发，风险驱动测试，PR 驱动审核，main 保持稳定。本文是共同工程规范的完整来源，根目录 [AGENTS.md](../../AGENTS.md) 只保留执行约束并引用本文。共同规范由后端 Agent 维护，前端 Agent 不同时编辑这两个文件。

## 分支与工作区

- main 是唯一稳定公共基线；禁止直接提交或推送 main。
- 默认从最新 `origin/main` 创建独立任务分支，一个任务对应一个分支、一个指向 main 的 PR。
- 后端使用 `feat/backend/<task>`、`fix/backend/<task>`、`refactor/backend/<task>`；治理、文档和工具维护使用 `chore/<task>`。前端业务任务对应使用 `feat/frontend/<task>`、`fix/frontend/<task>`、`refactor/frontend/<task>`。
- 开始任务记录父分支与基线 SHA。普通任务不建立多级父分支；大型功能确需多 PR 集成时，先获维护者明确批准，再建临时 epic 父分支，完成后删除。
- 前后端使用独立 Worktree，不同时修改同一目录，不在另一 Agent 的分支开发，不重复创建已有工作区。
- 创建分支前检查 Git 状态、当前分支和未提交修改；未知 WIP 不切换、覆盖或清理。另一 Agent 正在使用的 Worktree 不删除。
- 已合并且无剩余工作价值的任务分支及时删除本地、远程引用。不建立无明确任务目标的长期分支；移除 Worktree 前确认使用者、未提交与忽略文件，保护仍有价值的资料和 stash。
- 任务开始及提交审核前按需要刷新远程状态，不为普通读文件、改文档或每个 Commit 反复 fetch、创建工作区或重新集成历史。

已有且干净的后端 Worktree，可按以下最短流程开始任务：

```text
git status --short --branch
git fetch origin
git switch -c fix/backend/<task> origin/main
git rev-parse origin/main
```

存在 WIP 或同名分支时先核对归属与任务状态，不照抄上述切换命令；只有尚无合适工作区才创建 Worktree。

## Commit、PR 与合并

- 使用 Conventional Commits；scope 明确模块，例如 `feat(backend-document): support version export`、`fix(backend-auth): correct session validation`、`refactor(backend-blog): simplify publish flow`。
- 一个 Commit 有明确职责；精确暂存本任务文件，检查实际 Diff。禁止无检查地 `git add .`，不混入无关格式调整、重构、其他 Agent 的 WIP、凭据或本地测试产物。
- 完成实现和必要验证后提交、推送任务分支并创建 PR；不得只停留在暂存状态。不为美化历史反复重写已公开提交。
- PR 简述完成内容、接口/Schema 变化、验证等级及结果、风险和待决策事项。一个聚焦 PR 提供完整任务结果，普通任务不生成长篇开发、测试或交接报告。
- 审核要求修改时继续在该任务分支修复并执行受影响验证。未经维护者明确批准，不自行合并 main，也不借 epic 分支绕过 main 审核。
- 合并后确认远程 main 包含预期提交，再清理无用任务引用。不得强制覆盖 main；旧 Git 对象、Reflog 与分支引用是不同概念，不做破坏性历史清理。

## Minimum Sufficient Verification

先判断行为及影响范围，再选择验证等级和命令；等级取决于实际风险，不按文件数量划分。一个任务含多类变更时覆盖其最高实际风险，定向验证仍应围绕受影响范围。

| 等级 | 适用范围 | 最小充分验证 |
| --- | --- | --- |
| V0 | Markdown、README、纯注释/说明、Git/Commit/PR 整理、未改变行为的配置说明 | `git diff --check` 与必要内容、引用、格式检查；禁止运行 Maven 全量测试、Nuxt 构建或端到端测试 |
| V1 | 简单、低风险局部修改 | 仅直接关联的轻量检查；不默认完整项目构建 |
| V2 | 普通 Controller/Service、常规 Bug、局部接口及一般业务功能 | 受影响模块的功能测试及必要编译；通过后停止，不自动扩大全项目回归 |
| V3 | 认证/授权、权限边界、Schema/迁移、资源控制、破坏性 API、核心公共架构、关键跨模块链路 | 根据风险执行定向回归与必要真实集成；确有广泛影响时允许全量测试，不省略关键拒绝路径或数据一致性检查 |

配置描述可为 V0；真实配置值、运行行为或权限变化应按实际影响重新定级。V3 不自动扩大审批范围，审批事项见下文。

### 执行约束

1. 全量测试不是默认收尾。Git、文档或 PR 操作不触发重复应用测试。
2. 验证前明确受影响模块、风险与需要覆盖的成功/失败路径；选择直接相关测试，不为本轮另造大型测试框架。
3. 失败先定位根因，再复跑相关测试；只有后续修改或未解决影响证明有必要时才扩大回归。
4. 已通过且未受后续变更影响的检查不重复执行。复用结果须确认代码、依赖、配置和运行环境仍适用，并注明对应版本及复用范围。
5. 不为让错误测试通过而改变无关业务规则、降低断言或静默跳过。无法验证时明确报告，不能假装通过。
6. Mock 单元测试不能称为真实数据库、Redis、OSS 或浏览器联调。V3 所需真实写入使用隔离库、独立 Redis 命名空间及授权 OSS 测试对象，不动维护者现有数据。
7. 默认联调端口前端 3000、后端 9333；端口不能证明数据隔离。核对已有进程归属，不强行结束另一 Agent 或维护者的服务。
8. 测试通过只是最低条件。完成后仍检查业务事实来源、职责边界、重复规则、失败路径、配置/异常/日志及当前扩展点；发现明显结构问题不得宣布完成。

### 本地与 CI

本地承担最小充分的快速反馈；已启用 CI 承担仓库统一门禁。非关键任务不自行重复 CI 的耗时全量检查；尚无 CI 覆盖的必要验证也不能宣称已由 CI 完成。

前端现有命令为 `npm run typecheck`、`npm test`（Vitest）和 `npm run build`；定向单测可用 `npm run test -- app/test/<关联文件>.test.ts`。仅按等级选择与变更直接相关的检查，不把这组命令作为每个任务的必跑清单。后端同样选择受影响 Maven 模块、关联测试和必要编译，而非固定执行全量 verify。

当前没有 lint 脚本/ESLint 配置，也没有项目内 Playwright 依赖，不把这些写成已启用门禁；真实浏览器工具仍只在本地维护。

当前仓库未启用统一 CI 工作流。本轮只确定规范，不新建工作流、测试框架或修改分支保护。后续门禁启用应单独确认；本地 V0 任务仍不运行应用测试。需要额外发布验收时使用本地隔离工具，执行结果在 PR 中简述。

## Agent 职责与审批

后端 Agent 负责 Spring Boot、PostgreSQL/迁移、Redis、认证/授权/安全、Blog/Document/Asset、OSS 及后端 API/OpenAPI 契约。前端 Agent 负责 Nuxt 页面、组件、交互、渲染和性能。

重要接口变更先确定契约，再实施；需另一端配合时提供接口变化、所需修改和简短交接，不代改对方业务代码。共同规范只由后端 Agent 修改。

读取代码、实现已授权功能、必要局部重构、分级验证、修复自身问题、提交和创建 PR 可自主执行，不反复申请普通操作授权。以下事项须先获得明确批准：

- 重要架构调整、数据库破坏性变更。
- 认证/权限规则的业务语义变更、破坏性 API 修改。
- 跨越前端职责的大范围修改；其他前端业务修改也需明确授权。
- 合并 main、强制推送或重写公共历史。
- 变更 GitHub 保护/审批规则；自动合并亦须单独批准，不能绕过现有审核。

规范 PR 合并后，先确认 main 与 origin/main 一致；若 main 所在目录有他人 WIP，先保护并协调，不强行更新。后端从最新 main 开任务分支，阅读当前实现并核对未完成任务，保留有效业务决策，不重做基线迁移或全链路验收。旧任务已完成/失效时说明现状并提出具体候选，不擅自启动大型功能。

## 文件收录与日常交付

- 仅提交功能代码、功能单元测试与必要测试支撑、关键项目文档和安全配置模板。
- 本地集成/浏览器/性能脚本、密钥或测试数据生成工具保存在被忽略的本地目录；放进 `src/test`、`app/test` 也不能成为可提交工具。
- `docs/` 保留当前必要架构、业务流程及开发规范；运行说明放根目录 `quickstart.md`。验收、测试、审计、交接、进度报告以及截图、trace、录屏不入库。
- 根目录 AGENTS.md 是受版本控制的共同执行约束；其他本地 AI 工作流、凭据、日志、备份和构建产物保持忽略，不用 `git add -f` 绕过收录规则。
- 日常任务只报告完成内容、PR、验证等级及结果、关键风险或阻塞事项；没有实测的项目明确列为未验证，不生成无必要的开发日志。
